# 02 · 构建链路：从 LLM → Agent → 多智能体

> 从零构建一个 Agent 的完整步骤链。每步标注原书章节 + 一句判据。
> 用于：你已经决定要动手，按这条链路走，每步有明确的「做什么 / 怎么判断对错」。

## 链路全景

```
①设计观察/动作空间 → ②组织上下文 → ③建记忆知识 → ④接工具
   → ⑤执行+验证 → ⑥评估 → ⑦护栏上线 → ⑧持续进化 → ⑨多 Agent 扩展
   (Ch1)        (Ch2)       (Ch3)       (Ch4)   (Ch5)    (Ch7)   (Ch1/5/9)   (Ch9)      (Ch10)
```

## 各步要点

### ① 设计观察空间与动作空间（第 1 章）
- **做什么**：写清楚 Agent「能感知什么」（观察空间）和「能做什么」（动作空间），先于提示词。
- **判据**：能力边界由接口决定，不由模型决定——接口没设计好，换再强的模型也没用。

### ② 组织上下文（第 2 章）
- **做什么**：按「稳定前缀 / 易变尾部」组织；系统提示版本化 + 变更跑回归（像代码 CI）。
- **判据**：上下文累积爆炸时，先画分布再优化；KV Cache 与压缩**分开实测，别相加估算**。

### ③ 建记忆与知识库（第 3 章）
- **做什么**：先按三层次框架（工作/长期/元）定评估口径，再选存储格式（文本/向量/图谱/可执行代码）。
- **判据**：默认混合检索（稠密+稀疏）；概览查询用 RAPTOR、关系推理用 GraphRAG、层级导航用文件系统。

### ④ 接工具（第 4 章）
- **做什么**：先写工具描述（适用场景/输入输出/边界），再定粒度；高风险工具加确认与审计。
- **判据**：工具太多 → 渐进式披露 + 主动发现，别全量灌上下文；操作后立即自动验证（linter/回读）。

### ⑤ 执行 + 验证（第 5 章）
- **做什么**：生成 → 执行 → 验证（linter/测试）→ 错误恢复 → 沉淀经验。
- **判据**：编辑文件用精确编辑不用全文重写；沉淀经验要明确载体并定期「垃圾回收」规则集。

### ⑥ 评估（第 7 章）
- **做什么**：先定义「成功」再跑评估；指标按场景选（探索用 Pass@k、可靠性用 Pass^k）。
- **判据**：分数下降第一步查评测系统，第二步找失败簇，第三步才动 Agent；评判模型与 Agent 不同源。

### ⑦ 护栏上线（第 1、5、9 章）
- **做什么**：工具按风险分级（放行/确认/审计）；安全四要素全查（私有数据/不受信任内容/外部通信/持久记忆）；证据与指令隔离。
- **判据**：验证器、测试用例、发布门槛设为 Agent 不可自改。

### ⑧ 持续进化（第 9 章）
- **做什么**：三层轨迹验证（结果/过程/质量）；变更契约七要素（证据/根因/归属/提案/预期/受损/验证）。
- **判据**：保存经历 ≠ 从经历学习；新能力先进待验证区，过安全+回归再服务真实流量。

### ⑨ 多 Agent 扩展（第 10 章）
- **做什么**：先确认收益来自并行/分工/隔离，再决定要不要多 Agent；选拓扑（管理者/对等/去中心化）。
- **判据**：上线前逐条过六失败模式（并发冲突/错误级联/同质趋同/扯皮/循环失控/认知投降）。

## 配套工具（读完怎么用）

- **⑦ 护栏落地** → [agent-handrail](https://github.com/jackyjinggit)：边界/纪律/降级路径，把「安全部分」变成可配置资产。
- **⑥ 评估反谄媚** → [co-agency-integrity](https://github.com/jackyjinggit)：检测 Agent 是否在顺着你说（谄媚/方向带偏），补上「评估」里最容易被忽略的一环——AI 不骗你，才谈得上评估。
