# 01 · Agent 核心地图：6 大模块全景

> 全书 10 章归纳为 6 大模块。每模块：一句话定义 → 关键概念 → 作者核心论断 → 我的补充。
> 对应原书章节见括号。

## 总纲：Agent = LLM + 上下文 + 工具

```
        ┌─────────────┐
        │    LLM      │  大脑（推理）
        └──────┬──────┘
               │
   ┌───────────┼───────────┐
   │           │           │
┌──▼───┐  ┌───▼────┐  ┌───▼────┐
│ 上下文 │  │ 记忆/知识 │  │  工具   │
│ 眼睛  │  │ 长期记忆 │  │  手脚  │
└──────┘  └────────┘  └────────┘
       观察空间（能感知什么）× 动作空间（能做什么）
```

**核心执行模式 = ReAct 循环**：推理（Reason）→ 行动（Act）→ 观察（Observe）→ 循环至任务完成。

## 六大模块

### 1. 上下文工程（第 2 章）— 眼睛怎么睁
- **定义**：把模型需要的所有信息，在有限的上下文窗口里组织对。
- **关键概念**：Chat Template（system/user/assistant/tool 四角色）、KV Cache、稳定前缀、Skills 渐进式披露。
- **作者论断**：上下文决定能力上限；上下文学习本质是检索而非推理。
- **我的补充**：把「稳定前缀 / 易变尾部」分开设计——稳定放前命中缓存，易变后置。生产代码必须有 `max_iterations`。

### 2. 记忆与知识库（第 3 章）— 记住什么、忘什么
- **定义**：让 Agent 跨会话记住用户与事实。
- **关键概念**：三层次评估框架（工作/长期/元记忆）、RAG 管道（分块→嵌入→索引→检索→合成）、混合检索、RAPTOR/GraphRAG/文件系统。
- **作者论断**：记忆能力先定义「记什么、忘什么、怎么想起」再谈存储；混合检索是最稳的默认。
- **我的补充**：记忆内容必须可审计、可删除、日志脱敏前置——隐私是记忆系统的第一属性。

### 3. 工具（第 4 章）— 手脚怎么长
- **定义**：Agent 改变世界的通道。
- **关键概念**：感知/执行/协作三类工具、工具设计五原则、MCP、工具爆炸、执行-验证-反馈闭环。
- **作者论断**：工具设计本质是接口设计；「工具爆炸」的解法不是堆工具，是渐进式披露。
- **我的补充**：参数传递保真是隐性杀手——出错沿「字节→返回→序列化→模型→匹配」逐层找首个分歧。

### 4. Coding Agent（第 5 章）— 最通用的元能力
- **定义**：代码是 Agent 与工具世界对话的最通用方式。
- **关键概念**：代码五重身份、安全四要素（私有数据/不受信任内容/外部通信/持久记忆）、提议者-审核者。
- **作者论断**：通用 Agent 的内核都是 Coding Agent；经验沉淀 ≠ 持续进化。
- **我的补充**：提议者-审核者要带用户偏好信号，否则收敛到错误的局部最优。

### 5. 评估（第 7 章）— 尺子怎么拿
- **定义**：评估对象是「模型 + Harness 组合体」，不是模型。
- **关键概念**：Pass@k vs Pass^k、Rubric 四准则、失败归因（首错定位）、LLM-as-a-Judge 坑、统计显著性。
- **作者论断**：评估体系的首要价值是让你快速可靠地跟上变化；分数下降先查评测系统再动 Agent。
- **我的补充**：可靠性场景（支付/权限/部署）必须用 Pass^k——p=0.6,k=5 时 Pass@5≈99% 但 Pass^5≈7.8%，一个像「总能成」、一个像「总不出错」。

### 6. 多 Agent 协作（第 10 章）— 什么时候值得人多
- **定义**：多个 Agent 共享/隔离上下文、按拓扑协作。
- **关键概念**：上下文共享 vs 隔离、拓扑（对等/管理者/去中心化/A2A）、六种失败模式。
- **作者论断**：多 Agent 不一定优于单 Agent——优势在并行、分工、外部世界隔离，不在「人多力量大」。
- **我的补充**：上线前逐条过六失败模式清单（并发冲突/错误级联/同质趋同/互相扯皮/循环失控/认知投降）。
