# 03 · 关键工程决策：书里反复出现的权衡

> 提炼全书 8 组核心工程权衡，决策视角：作者为什么这么选，什么场景下可以换个选法。
> 适合：已经读完全书/地图，遇到具体决策时回来查。

## 决策清单

### D1 · 编排：工作流 vs 自主 Agent（第 1 章）
| | 工作流 | 自主 Agent |
|---|---|---|
| 适合 | 任务确定、步骤可预期 | 开放探索、需试错 |
| 代价 | 不灵活 | 不可控、需护栏 |
| **选法** | 任务确定度高 → 工作流；低 → 自主；**同一系统可两者并存**（按任务分派） |

### D2 · 记忆存哪：写进参数 vs 存进知识库（第 3、8 章）
| | 写进参数（LoRA） | 存知识库（RAG） |
|---|---|---|
| 优势 | 检索零延迟、个性化强 | 灵活、可审计、可迭代 |
| 代价 | 更新重、回归贵 | 依赖检索质量 |
| **选法** | 要低延迟个性化 → 参数；要可审计可迭代 → 库；事实/规律分载体拆 |

### D3 · 检索：稠密 vs 稀疏（第 3 章）
- 稠密嵌入抓语义、稀疏抓精确词匹配。
- **选法**：默认混合检索；查询偏精确词匹配 → 加重稀疏权重，偏语义 → 加稠密。只押一边必漏。

### D4 · 工具粒度：整合 vs 分离（第 4 章）
- 整合（少而全）降调用成本；分离（细而专）提复用。
- **选法**：高频核心操作 → 整合；低频/独立能力 → 分离。先写描述再定粒度。

### D5 · 评估指标：Pass@k vs Pass^k（第 7 章）
- Pass@k = k 次至少成一次（能力天花板）；Pass^k = k 次连续全对（可靠性）。
- **选法**：探索/科研用 Pass@k；支付/权限/部署用 Pass^k，且设一票否决项（幻觉/安全违规满分归零）。

### D6 · 评判模型：同源 vs 异构（第 7 章）
- 同源（Agent 与评判同家族）→ Goodhart 钻评判偏好盲区。
- **选法**：多源异构评判（不同家族 LLM 分别评），偏见正交难同时欺骗。

### D7 · 多 Agent：要不要上（第 10 章）
- 纯文本推理任务，等量计算下多 Agent 并不优于单 Agent。
- **选法**：收益来自并行/分工/外部世界隔离 → 上；否则单 Agent + 好 Harness 更省。

### D8 · 经验沉淀载体（第 5、9 章）
| 载体 | 适合 | 判据 |
|---|---|---|
| 经验知识库 | 事实/规律/例外+来源 | 可检索、可审计 |
| Prompt+Skill | 可语言化的判断原则 | 易膨胀 → 定期垃圾回收 |
| 程序+Harness | 高风险硬约束、可验证 | 开发维护成本高但最可靠 |
| 模型参数 | 高维感知/风格/隐式策略 | 更新回归成本高 |

## 贯穿全书的元原则

1. **先定义「成功」再跑评估**（第 7 章）——「说了做了」≠「系统真的变了」。
2. **一轮只改一个变量**（第 7 章）——原书在 AndroidWorld 上的三轮迭代：H1 加提示无效 → H5 换 accessibility feed 达 100% 但 token 2.5× → H5C 精简节点仍 100% 且 token 减半。每一轮只动一个变量，才能归因。
3. **保存经历 ≠ 从经历学习**（第 9 章）——学习发生在主动提炼之后，不是日志写入那一刻。
4. **安全机制不可自我修改**（第 9 章）——Agent 能改验证器，就能降低阈值伪装进步。
