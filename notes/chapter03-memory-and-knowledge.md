# 精读笔记 · 第 3 章《用户记忆和知识库》

> 来源：李博杰《深入理解 AI Agent：设计原理与工程实践》第 3 章（结构精读）
> 本文为加工产物：基于章节结构与关键要点提炼，供落地实践复用

---

## 一、核心认知

1. **记忆分层次，评估先于建设**——记忆能力用三层次框架评估（工作记忆/长期记忆/元记忆），先定义「记什么、忘什么、怎么想起」再谈存储。
2. **RAG 不是检索器的堆砌，是知识获取管道**——分块（Chunking）→ 嵌入 → 索引 → 检索 → 合成，每一环都影响答案质量。
3. **混合检索是最稳的默认**——稠密嵌入抓语义、稀疏嵌入抓精确词匹配，二者互补；只押一边都会漏。
4. **超越扁平文本**：结构化索引（RAPTOR 层次摘要树 / GraphRAG 实体关系图 / 文件系统范式）按查询类型各有所长。

## 二、可操作框架

### 2.1 记忆的三层次评估框架

| 层 | 问什么 | 对应机制 |
|---|---|---|
| 工作记忆 | 当前任务上下文够不够 | 上下文窗口/状态栏 |
| 长期记忆 | 跨会话记住多少、多久 | 记忆存储/知识库 |
| 元记忆 | 知道自己知道/不知道什么 | 检索触发判断/置信度 |

### 2.2 用户记忆的存储格式（四种）

1. 文本/结构化条目（最简单）
2. 向量（语义检索）
3. 图谱/关系（实体链接）
4. **可执行代码**（进阶：记忆即函数/规则，可验证可执行）

### 2.3 RAG 管道要点

- **分块（Chunking）**：块大小/重叠/语义边界——决定检索颗粒度
- **稠密嵌入**：语义相似；**稀疏嵌入**：关键词精确匹配
- **混合检索**：两路召回 + 融合排序
- **上下文感知检索**：把原始文档上下文附加到分块——但原文档本身混乱/矛盾时可能放大错误（需信息质量信号）

### 2.4 结构化索引选型

| 索引 | 擅长 | 结构 |
|---|---|---|
| RAPTOR | 跨块主题/概览类查询 | 自底向上层次摘要树 |
| GraphRAG | 实体关系/多跳推理 | 实体-关系图 |
| 文件系统范式 | 层级导航、路径寻址 | 树状目录 |

## 三、常见坑

1. 分块策略随意（过大丢失局部、过小丢失语境）
2. 只做稠密或只做稀疏检索，漏召回
3. 检索结果不标来源，模型幻觉「记得」
4. 记忆不做脱敏，日志带隐私
5. 上下文感知检索传播源文档的错误/矛盾

## 四、工程判据（决策清单）

- **要建记忆系统** → 先用三层次框架定评估口径，再选存储
- **选检索方式** → 默认混合检索；查询偏精确词匹配加重稀疏权重，偏语义加稠密
- **选索引结构** → 概览类查询用 RAPTOR、关系推理用 GraphRAG、层级导航用文件系统
- **隐私** → 日志脱敏前置，记忆内容可审计可删除
- **未来性判断** → 「领域知识库还会重要吗？」——基座模型增强会挤压外部库的价值，但实时/私有/可审计知识仍要靠库
