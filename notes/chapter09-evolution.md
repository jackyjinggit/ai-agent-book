# 精读笔记 · 第 9 章《Agent 的持续进化》

> 来源：李博杰《深入理解 AI Agent：设计原理与工程实践》第 9 章（本地精读）
> 本文为加工产物：把章节内容提炼为「核心认知 / 可操作框架 / 常见坑 / 工程判据」，供落地实践复用

---

## 一、核心认知

1. **保存经历 ≠ 从经历学习**——把轨迹放进向量库不会自动完成「评价、对照、归纳、验证」；学习发生在主动提炼之后，不是日志写入那一刻。
2. **学习信号先于总结**——持续进化起点不是「反思」而是「评价」；错误评价进入长期知识会跨任务放大。
3. **自我进化的上限不取决于模型写多好的代码，取决于承载系统的可组合性**——时间可组合性=改了什么能否撤销；空间可组合性=依赖什么能否声明解析。

## 二、可操作框架

### 2.1 三层轨迹验证（结果 / 过程 / 质量）

| 层 | 验证什么 | 载体 |
|---|---|---|
| 结果验证器 | 事情是否真办成 | 测试/数据库/工具返回（环境真值） |
| 过程验证器 | 是否以允许的方式办成 | 业务规则/权限/动作序列 |
| 质量验证器 | 是否办得合适 | LLM Rubric（逐项给分+引用证据） |

> 越靠下越依赖代码/环境真值，只有难形式化的才交给 LLM。多数团队的「断言/校验」只覆盖结果层，缺过程层与质量层。

### 2.2 四种更新载体（选择判据）

| 载体 | 适合 | 局限 |
|---|---|---|
| 经验知识库 | 事实/经验规律/例外+来源 | 依赖检索与正确应用 |
| Prompt+Skill | 可语言化的判断原则 | 易膨胀/冲突/被忽略 |
| 程序+Harness | 可确定解析/可执行验证/高风险硬约束 | 开发维护成本高 |
| 模型参数 | 高维感知/风格/隐式策略 | 更新回归成本高 |

**判据**：按「能力的表示性质」选载体，不是按「任务是否稳定」；可拆多载体（事实→知识库、例外→Skill、权限→程序、高维→参数）。

### 2.3 可证伪的变更契约

每次修改请求 = 契约：**失败证据 → 推断根因 → 归属组件 → 修改提案 → 预期修复行为 → 可能受损的既有行为 → 分别验证两者的用例**。
多数团队的变更登记只有「改了什么」，缺「为什么改/预期/可能受损/验证」。

### 2.4 安全边界三隔离

1. **证据与指令隔离**：网页/工具输出及其 LLM 摘要 = 不可信证据，不能当指令执行、不能直接进能力库
2. **待验证与正式能力隔离**：新知识/Prompt/Skill/程序先进待验证区，过安全+回归才服务真实流量
3. **安全机制不可自我修改**：Agent 不能改验证器/测试用例/发布门槛/审计日志/稳定备份（否则降低阈值即可伪装进步）

### 2.5 更新 ≠ 受益（评估分维度）

能力写得好（更新器能力）≠ 任务 Agent 会正确加载使用（受益能力）。
评估不能只用端到端分数反推更新器好坏——需分维度：更新提案有效率 / 产物激活率 / 遵循成功率 / 保留任务集增益。

### 2.6 双循环 + 睡眠学习

- **在线执行循环**（完成任务+记录证据）↔ **离线进化循环**（聚合轨迹→诊断根因→生成提案→验证发布）——通过版本化经验库+评估集连接
- **睡眠学习五步**：触发（门槛）→ 定向（读已有能力）→ 采集整合（合并/标记冲突）→ 验证审批（迁移集/保留集/安全集）→ 修剪索引（归档/删除，保留来源+回滚）

### 2.7 需求澄清 Skill（问多少的平衡）

「问得太少导致返工，问得太多增加打扰」：

1. 判断歧义度/风险/返工成本
2. 低风险小改动 → 说明假设直接执行
3. 高风险 → 集中少量真问题
4. 生成 Spec（目标/非目标/取舍/假设/验收）确认
5. 执行中 Spec 不成立 → 暂停重确认

## 三、常见坑

1. 以为「存了轨迹」就是「学到了」——学习发生在主动提炼之后
2. 反思/总结先行，不做评价——错误评价会跨任务放大
3. 只验结果不验过程/质量（「办成了」但「方式违规/质量差」）
4. 安全机制可被 Agent 自我修改（降低阈值伪装进步）
5. 用端到端分数反推更新器好坏（更新≠受益）
6. 新能力直接进生产，不过待验证区

## 四、工程判据（决策清单）

- **要建持续进化系统** → 先定三层验证器（结果/过程/质量），再谈「学习」
- **新知识/技能落地** → 先进待验证区，过安全+回归再服务真实流量
- **改一条行为** → 按变更契约七要素写清（证据/根因/归属/提案/预期/受损/验证）
- **安全红线** → 验证器、测试用例、发布门槛、审计日志设为 Agent 不可改
- **沉淀经验** → 按「表示性质」选载体（事实→知识库、例外→Skill、权限→程序、高维→参数）
- **评估进化效果** → 分维度（提案有效率/激活率/遵循率/保留增益），不只看端到端
