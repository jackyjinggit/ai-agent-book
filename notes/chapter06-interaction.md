# 精读笔记 · 第 6 章《交互：观察与动作空间的扩展》

> 来源：李博杰《深入理解 AI Agent：设计原理与工程实践》第 6 章（结构精读）
> 本文为加工产物：基于章节结构与关键要点提炼，供落地实践复用

---

## 一、核心认知

1. **交互是观察与动作空间的扩展**——模态与触发时机（同步请求 → 异步事件）扩展了 Agent 能感知什么、何时行动。
2. **异步与事件驱动是刚需**：世界会主动找上门（消息/通知/事件），Agent 必须能被打断、能处理事件，而不只是被调用。
3. **语音三范式**：级联流水线（Cascading）/ 端到端全模态（Omni）/ 全双工交互——延迟与智能上限是两条独立曲线，**交互架构可以独立于模型能力改进**。
4. **Computer Use 两条路线**：结构化（DOM/Accessibility Tree 索引）vs 纯视觉（坐标预测）——标准 Web 应用结构化赢，Canvas/自绘控件只能靠视觉。

## 二、可操作框架

### 2.1 异步与事件驱动

- **为什么需要异步**：长任务/等待外部输入时，同步阻塞浪费
- **事件触发工具 + 用户沟通工具 + 虚拟身份与隔离执行环境**
- **如何让同步模型支持异步打断**：事件注入、优先级抢占、上下文切换
- 深层矛盾：模型是同步的，世界是异步的——架构补偿，不是模型补偿

### 2.2 语音三范式对比

| 范式 | 结构 | 优势 | 代价 |
|---|---|---|---|
| 级联流水线 | ASR→LLM→TTS 分步 | 每环节可替换/可观测 | 延迟累积、错误级联 |
| 端到端全模态（Omni） | 单一模型多模态 | 低延迟、上下文共享 | 迭代慢、难观测 |
| 全双工交互 | 边听边说（如 MPS 双脑） | 打断自然、实时 | 复杂度高、认知时序矛盾 |

### 2.3 Computer Use

- **动作空间设计**：开放坐标预测 vs 封闭 ID 选择（SoM/DOM 元素索引）——封闭 ID 更稳但需先标注元素
- **视觉定位（Grounding）**：界面元素 → 可操作目标
- 非标准控件/动态界面 → 标注不完整 → 回退坐标预测

### 2.4 机器人/VLA（延伸）

- **动作分块（action chunking）**：一次生成一小段未来动作，控制线程高频回放——推理延迟隐藏在执行时间里；但环境突变（物体被移走）→ 预生成动作失效

## 三、常见坑

1. 同步模型硬扛异步世界 → 事件堆积/漏处理
2. 级联语音错误累积（ASR 错 → LLM 错 → TTS 错）
3. Computer Use 押注单一路线（纯视觉或纯结构化），非标准界面崩
4. 动作分块假设环境静态，环境突变无响应
5. 交互与智能同步提升的误区——交互架构可以单独优化（快慢分工）

## 四、工程判据（决策清单）

- **Agent 要接外部事件** → 设计事件触发 + 优先级 + 隔离执行环境，别让同步循环阻塞
- **语音交互** → 要可替换/可观测选级联；要低延迟选端到端；要自然打断选全双工；可考虑快慢分工
- **Computer Use** → 标准 Web 用结构化索引（DOM/AT），自绘界面配视觉路线；动态界面留坐标回退
- **动作序列** → 分块生成 + 执行期环境校验（变化即重规划）
- **交互升级** → 优先改交互架构（延迟/可观测性），不必等模型上限同步提升
