## 一、核心认知

1. **现代 Agent = LLM + 上下文 + 工具**——LLM 是大脑、上下文是眼睛、工具是手脚；观察空间（能感知什么）与动作空间（能做什么）是模型与世界的接口。
2. **ReAct 循环是 Agent 的核心执行模式**——推理（Reason）→ 行动（Act）→ 观察（Observe），循环直至任务完成。
3. **Harness 工程 = 模型之外的竞争力**——从「提示工程」到「Loop 工程」：模型能力趋同后，上下文组织、工具编排、反馈循环、护栏决定成败。
4. **「模型即 Agent」范式下，Harness 的重要性反而增加**——模型在工具调用上越来越自主，但让它安全、可靠、可观测地自主，正是 Harness 的活。

## 二、可操作框架

### 2.1 Harness 五要素

| 要素 | 含义 | 对应「构建」部分 |
|---|---|---|
| 模型 | 选择什么 LLM | 第 8 章后训练 |
| 上下文 | 眼睛：指令/记忆/知识/轨迹 | 第 2、3 章 |
| 工具 | 手脚：感知/执行/协作 | 第 4 章 |
| 编排 | 工作流 vs 自主、循环控制 | 全书贯穿 |
| 护栏 | 安全/权限/风险分级 | 各章安全部分 |

### 2.2 构建有效 Agent 的核心原则

- **观察空间与动作空间要显式设计**：Agent 能感知什么、能做什么，先于「提示词」决定能力边界
- **消融实验验证组件价值**：关掉某组件看性能变化（例：工具结果反馈缺失 → 无限循环）
- **护栏按工具风险分级**：低风险工具直接放行，高风险工具（删除/支付/权限）加确认与审计

### 2.3 编排模式：工作流 vs 自主

| 维度 | 工作流 | 自主 Agent |
|---|---|---|
| 任务确定性 | 高（步骤可预期） | 低（需探索） |
| 可控性 | 强 | 弱 |
| 适用 | 固定流水线 | 开放任务 |
| 混合 | 同一系统可两种模式并存（按任务分派） | |

## 三、常见坑

1. 只调提示词，不设计观察/动作空间——能力上限被接口而非模型锁死
2. 工具结果缺失/超时无兜底 → Agent 无限循环
3. 高价值工具无风险分级，误删/误支付
4. 自主模式塞进确定任务，失控不可观测

## 四、工程判据（决策清单）

- **开始搭 Agent** → 先写清楚观察空间 + 动作空间清单
- **不确定组件有没有用** → 跑消融实验（一次关一个）
- **选编排模式** → 任务确定度高用工作流，开放探索用自主；两者可混
- **上线安全** → 工具按风险分级（放行/确认/审计），高价值操作留痕迹
- **诊断循环卡死** → 先查工具结果是否回传、循环是否有终止条件
