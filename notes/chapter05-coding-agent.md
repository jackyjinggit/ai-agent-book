# 精读笔记 · 第 5 章《Coding Agent 与通用 Agent》

> 来源：李博杰《深入理解 AI Agent：设计原理与工程实践》第 5 章（结构精读）
> 本文为加工产物：基于章节结构与关键要点提炼，供落地实践复用

---

## 一、核心认知

1. **Coding 是 Agent 的基础能力，也是通用 Agent 的元能力**——从 Manus 到 OpenClaw，通用 Agent 的内核都是 Coding Agent；代码是 Agent 最通用的「与工具世界对话」的方式。
2. **代码的五重身份**：思考工具（边写边想）/ 业务规则的约束（代码即规则，可验证）/ 系统适配器 / 生成式 UI / **代码创造代码（Agent 自举）**。
3. **安全四要素**：Simon Willison「致命三要素」（访问私有数据 + 暴露于不受信任内容 + 具备外部通信能力）+ 本书补充第四要素——**持久记忆**。
4. **经验沉淀 ≠ 持续进化**：把经验写回代码库/知识库只是沉淀；一次成功的代码修改不能直接视为第九章的持续进化（缺评估闭环与验证）。

## 二、可操作框架

### 2.1 Coding Agent 整体流程

需求理解 → 规划 → 代码生成 → **执行 + 验证（linter/测试）** → 错误恢复 → 沉淀经验

### 2.2 Harness 工程在 Coding Agent 中的实践

- **故障与错误恢复**：错误分类（流程缺失/工具调用错/格式错/复制错/模型执行异常/完成度判断）→ 按类归因
- **搜索工具**：定位相关代码/文档（检索质量决定改得对不对）
- **文件编辑工具**：精确编辑优于全文重写；编辑后验证
- **提议者-审核者机制**：生成后由独立 reviewer 审（PPT/视频/日志可视化反复用）——但 reviewer 偏好与用户不一致会收敛到错误局部最优

### 2.3 经验沉淀的多种载体

写入知识库文件 / 更新架构文档 / 维护项目指令文件 / 把操作序列固化为代码——**但规则集会随时间膨胀，需要「垃圾回收」**（识别并清理冗余/过时条目）

### 2.4 代码作为元能力

- 代码作为业务规则约束：把「必须/禁止」写成可执行校验，比提示词可靠
- 日志解析等场景：代码自动跟随格式演化——但要区分「需要适应的变化」vs「需要报告的异常」（适应 bug 会掩盖问题）

## 三、常见坑

1. 全文重写而非精确编辑 → 改坏未触及部分
2. 经验只沉淀不回收 → 规则集膨胀 → 提示词熵增
3. 提议者-审核者同质（reviewer 偏好=作者偏好）→ 收敛错误
4. 代码生成后不验证 → 错误进入产物
5. Agent 自举（代码创造代码）无代际防退化 → 错误累积

## 四、工程判据（决策清单）

- **通用 Agent 起步** → 先具备 Coding 能力（它是最通用的执行通道）
- **编辑文件** → 精确编辑 + 编辑后验证（linter/测试/回读）
- **沉淀经验** → 明确载体（知识库/文档/指令/代码），并定期做规则垃圾回收
- **生成类任务** → 用提议者-审核者，且 reviewer 要带用户偏好信号
- **安全设计** → 四要素全查：私有数据/不受信任内容/外部通信/持久记忆
- **代码自适应 vs 报告异常** → 变化先判「预期 vs bug」，再决定适应还是上报
