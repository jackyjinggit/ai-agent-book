## 一、核心认知

1. **后训练四阶段全景**：预训练（预测下一个词）→ Mid-training（在目标分布上继续学习）→ SFT（换了数据的「预测下一个词」）→ RL（按奖励优化）。每阶段解决不同问题。
2. **SFT 与 RL 的本质区别**：SFT 学「怎么答对」，RL 学「什么值得做」——有明确可判奖励时 RL 更强，只有示范数据时 SFT 够用。
3. **先补底座，再做 SFT/RL**：基座能力不足（pass@1 太低）时直接微调是浪费——先 Mid-training 补知识/基础能力。
4. **评估与训练集必须分离**：把评估集用于训练违反基本法则；动态参数生成（τ²-bench）与参数化模板（AndroidWorld）只是缓解，不是解决。

## 二、可操作框架

### 2.1 何时选哪个阶段

| 症状 | 该做什么 |
|---|---|
| 缺领域知识/基础能力 | Mid-training（构造目标分布数据） |
| 有示范数据、任务可模仿 | SFT（数据合成：从示范到可训练轨迹） |
| 有明确奖励、要优化行为策略 | RL（On-Policy 优先，从 16 次 rollout 到一次参数更新） |
| 不确定 | 联合 pass@k、格式解析率、部分进展率、失败归因判断阶段切换 |

### 2.2 RL 要点

- **为什么 LLM RL 通常优先 On-Policy**：策略分布实时反馈，样本效率与稳定性折中
- **RL 环境：从评估到仿真**——环境是模型练习的场地；造不出环境就让模型扮演环境
- **PRM vs ORM**：过程奖励模型评每步 vs 结果奖励模型只评最终——「正确过程错误结果」vs「错误过程侥幸正确」如何奖励，是设计取舍

### 2.3 数据合成与微调成本

- SFT 数据合成：从人工示范 → 可训练轨迹（覆盖失败修复、多轮交互）
- LoRA 微调成本不高——「记忆写入参数」vs「记忆存入知识库」按场景选（写入参数=检索零延迟但更新重；存库=灵活可审计但依赖检索）

## 三、常见坑

1. 基座能力不足直接 SFT/RL（先补底座）
2. 评估集污染训练集（独立性破坏）
3. 结果奖励掩盖过程错误（ORM 只评结果）
4. 短预算领先外推长程（RE-Bench 教训）
5. 学生模型与教师模型同源（蒸馏无增益；Weak-to-Strong 提示弱信号可激发强模型——反向可能）

## 四、工程判据（决策清单）

- **目标任务 pass@1 很低** → 先看是缺知识（Mid-training）还是缺示范（SFT）还是缺策略（RL），别直接上 RL
- **奖励可定义** → RL；**只有示范** → SFT
- **评估** → 独立数据集 + 动态生成缓解模板固定问题
- **要低延迟个性化** → 考虑 LoRA 写入参数；**要可审计可迭代** → 存外部知识库
- **RL 环境缺失** → 先造环境，造不出用模型扮演，再谈训练
